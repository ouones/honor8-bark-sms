# 荣耀8短信转发至 Bark

## 1. 问题与方案

用户需要将荣耀8 SIM1 中国移动卡收到的全部短信转发至 iPhone 15 Pro，主要用于验证码。现有 V2.2 模块通过 Root Shell 轮询短信 Provider，只实现钉钉格式推送，每轮仅处理最新一条短信，且依赖目标设备当前命令路径中不存在的工具，不能直接满足需求。

本次在原有 Magisk 模块上增量修改：补充 EMUI 8 与 Bark 路径，按发送进度读取全部待发短信，每条短信发送一条通知，失败后从系统短信库重读补发。只持久保存少量发送进度，不增加短信正文副本、独立消息队列或新数据库。

本文件规定后续实现与验收，不表示功能已实现。用户要求继续 `to-spec` 视为进入规格阶段的明确指令，无需重复访谈。

## 6. 短信读取与进度契约

### 6.1 内容来源与选择

- 仅处理系统收件箱中、属于目标 SIM1 订阅的短信；不以“验证码”等关键词过滤短信。订阅关系通过 `content://telephony/siminfo` 的 `_id` 和 `sim_id` 取得。
- 无法确定目标订阅时保留进度并等待下轮，不把未知订阅当作目标卡，不向系统短信库写入或修改记录。
- 查询只选择必要列：记录 ID、原始接收时间、订阅 ID、发件人和正文。发件人及正文在查询输出阶段编码为十六进制，再解码原始 UTF-8，避免正文换行、逗号、`date=` 或 `Row:` 被误当作记录边界。
- 查询、解析错误与“成功查询但没有记录”分开处理；不能仅凭 `content` 的进程退出码判断成功，也不能把错误结果当作空库。

### 6.2 进度格式与首次边界

- 进度为 `date` 与 `_id` 的有序二元组；先比较接收时间，再比较同一时间内的记录 ID，不再只比较时间戳，也不假定 `_id` 永不复用。
- 进度文件固定为模块目录内的 `state/sms.cursor`，内容为一行、两个非负十进制整数，依次为 `date` 与 `_id`，以空格分隔；不保存号码、正文、验证码或请求体。
- 目录仅 Root 可访问，文件仅 Root 可读写；使用同目录临时文件加原子替换写入，写入失败不继续发送后续记录。
- 首次没有进度文件时，成功读取目标收件箱当前最大的二元组并保存为边界，不发送已有短信；成功确认空库时保存 `0 0`。初始化查询或写入失败时保持未初始化，等待重试，不默认回放历史。
- 后续重启加载已有进度，禁止重新以最新短信覆盖进度；内容不合法的进度文件需报错停止，不自动跳过待发短信。
- 现有 `last_sms_date.txt` 不包含完整新进度，且设备未安装本项目；本次不实现旧状态迁移，不将旧文件当作有效新进度。

### 6.3 逐条发送与失败恢复

- 查询二元组严格大于当前进度的记录，按二元组升序排列，每批最多50条；该上限为内部常量，不增加配置项。
- 顺序发送每条记录。只有对应 Bark 请求确认成功后，才将进度推进到该记录；不得先推进到批次最大值。
- 任何一条发送、解析或进度写入失败，本轮停止继续发送，保留已成功提交的进度；经过正常轮询等待后重读系统短信库，不并发发送，不创建待发队列。
- 新轮次只重读仍存在的记录。待发源短信被删除后无需恢复，不因 ID 缺口卡住后续记录；已读取内容不跨轮次保存用于重发。
- 网络响应丢失或成功后进度尚未写入即退出，可能引发重复通知，符合已确认取舍；不新增严格去重或“恰好一次”机制。
- 系统短信数据库结构不变，不新建业务数据库，不保存短信持久副本；不实现历史导入、短信库重建或人为回拨系统时间后的进度修复。

## 7. Bark 请求与通知契约

- 使用单目标、UTF-8 JSON POST，将 `device_key`、`title`、`body` 及识别成功时的 `copy` 放入请求体。标准 `/push` 和这些参数见 [Bark 官方教程](https://github.com/Finb/Bark/blob/master/docs/tutorial.md)与[参数说明](https://github.com/Finb/Bark/blob/master/docs/params.md)。
- 正文包含发件人、原始接收时间和完整短信正文；时间显示为设备本地时间，并使用原记录的毫秒时间值转换，不使用补发时的当前时间。
- 有验证码时标题为短信标识加验证码，`copy` 为验证码本身；没有识别结果时使用普通短信标题，不传 `copy`，仍完整转发。复制操作遵循 Bark 行为，不承诺 iOS 自动读取或自动粘贴验证码。
- 复用现有“验证码”与英文 `code` 附近4至8位纯数字的识别范围，修正实际测试暴露的问题；多候选时使用固定、可测试的匹配顺序，不增加字母数字混合码、语义模型或服务商规则库。
- JSON 必须正确传递中文、双引号、反斜杠、换行、回车、制表符和表情，不能将短信内容当作 Shell 命令或格式字符串执行。
- 正文及请求体只在当前进程内存和管道中使用，不落盘为载荷文件或重发副本；日志不记录短信全文、验证码或 key。
- 请求成功必须同时满足：客户端成功退出、HTTP 200、JSON 顶层业务字段 `code` 为数值200。空响应、HTML、错误业务码、连接错误和超时均为失败，不能因响应中任意出现字符串200就推进进度。标准响应依据为 [Bark 路由](https://github.com/Finb/bark-server/blob/master/route_push.go)及[响应定义](https://github.com/Finb/bark-server/blob/master/router.go)。
- 发送成功只表示服务端确认接收，不等于 iPhone 已展示通知；10秒目标通过真实接收端单独验收，不增加手机回执协议。
- HTTPS 客户端固定连接超时3秒、单次总超时5秒，沿用轮询间隔作为失败重试等待，不叠加客户端内部无限重试；正式外网接口使用 HTTPS 并验证证书，不通过关闭证书校验解决兼容性。进程级测试可使用本地 HTTP 服务。
- 不主动设置额外铃声、强提醒、通知存档、有效期、分组或加密参数，沿用接收端现有默认行为。

## 8. 启动、依赖、安装与代码开销

- 保留 Magisk 模块入口和原模块 ID，修正其实际启动环境：通过已核验的 Magisk BusyBox ash 运行核心脚本并启用 standalone 模式，使 `awk` 等使用确定的实现。官方机制见 [Magisk 开发指南](https://topjohnwu.github.io/Magisk/guides.html)。
- 原项目没有网络二进制依赖清单。实现阶段选用可在 Android 8 ARM64 执行的 curl 制品，固定版本，记录来源、SHA-256、许可及证书来源，并在目标设备执行验证；安装阶段不临时从网络下载工具。
- 不假定 Magisk 自带 wget 支持所需 POST/JSON/TLS 功能；本次设备的 wget 帮助中未提供 POST 选项，不能据其存在就判定网络依赖满足。
- 防止重复启动导致多个守护进程同时推进同一进度，使用现有平台工具能完成的最小互斥方式，不另建监控服务。
- `customize.sh` 对 Bark 只验证 Bark 必填项，不能强制要求 `WEBHOOK_URL`；安装流程中已有系统与功能选项只修改与本次配置有关的部分，不新增界面或通用安装框架。
- 空闲时默认每5秒一轮，不扫描完整历史、不发送网络心跳、不反复读取通话记录、不为每条历史记录启动独立循环。每轮查询需有超时界限，失败路径必须等待，不能忙循环。
- 保留日志轮转，默认单文件上限1 MiB且最多一个备份；空轮询不写日志，错误只记录必要原因，禁止持续累积载荷文件。
- 省电和低占用通过以上代码行为与运行观察验证，不追加用户供电或联网习惯调查，不承诺未经测量的每日耗电百分比。
- 文本修改保持 UTF-8 无 BOM 与 LF，写入中文后严格解码验证；只修改本规格要求的源码和说明，不批量格式化旧代码。

| AC-13 | 连续空轮询、持续请求失败、尝试重复启动、日志越界 | 有等待和请求/查询超时，守护进程单实例，日志轮转，无通话查询或心跳 | US-11 |
| AC-14 | 扫描运行产物、日志、打包内容及 Git 差异 | 无短信持久副本和真实密钥提交；主分支及无关源码保持基线 | US-09、US-14 |

静态检查需覆盖修改脚本的语法、UTF-8 无 BOM、LF 和 `git diff --check`。不新增与本次需求无关的格式、性能基准或覆盖率工程。

## 10. 明确不在范围内

- Telegram、新推送平台、双渠道冗余、多设备推送及服务端建设。
- 通话提醒的新增或修复，钉钉、其他机型、KernelSU/APatch 的兼容保证；不因它们不在本次验证范围而删除无关旧代码。
- 验证码专属过滤、发送短信、修改系统短信的已读状态、联系人查询。
- 短信正文持久存储、消息队列、新数据库、独立存档、被删除短信恢复、首次历史回放及旧时间戳状态迁移。
- SMS 库重建、历史导入、换卡迁移、人为回拨时间后的自动修复，以及多用户空间适配。
- 严格恰好一次投递、iPhone 展示/阅读回执、新的端到端加密、自动粘贴或自动填验证码。
- 重写为 Android App、LSPosed Hook、常驻前台服务、保活工具套件或通用渠道插件框架。
- 电池使用习惯、网络环境规划、手机系统设置改造或未经实测的耗电保证。
- 本规格阶段的功能编码、刷入、重启、发送真实短信、发布或合并主分支。
